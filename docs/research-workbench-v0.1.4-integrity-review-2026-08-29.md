# Research Workbench v0.1.4：科研前台与执行内核一致性复核

日期：2026-08-29

## 发布结论

这一轮完成的是 v0.1.3“领域判断在前、执行状态在后”的底层闭环。研究者前台继续只回答四类问题：这个领域目前知道什么、主要依据是什么、哪些判断仍受证据边界限制、下一项需要研究者作出的决定是什么。状态机、Pi Agent 工具循环、版本、哈希与恢复细节继续留在技术审计和服务端。

同时，前台动作不再由页面根据零散状态自行推测。服务端根据同一份持久化研究记录生成唯一的可执行动作，工作台按钮与用户简报都读取这份契约；遇到版本冲突、旧报告、越级请求或中断运行时默认拒绝。

## 本轮新得到的产品判断

1. **领域结论与选题探索必须分账。** 建项前的题名摘要扫描可以支持领域定位和候选方向，但不能自动成为正式报告结论。v0.1.4 切断了旧预览混入新报告的路径。
2. **两轮选题校准必须可恢复，也必须不可跳步。** 第一轮计划、校准与预览，研究者方向选择，以及第二轮计划、校准与预览均写入追加式记录；服务重启后可以继续，但客户端不能替换候选顺序、查询式或方向决定。
3. **胶水逻辑只负责传递科研动作，状态机负责守住科研边界。** 前台用自然语言呈现“核对并作出研究决定”等动作；后台验证动作是否与当前项目版本、报告版本和研究者决定一致。
4. **恢复不能伪造成功。** 进程中断遗留的 Agent 运行会记录为取消和失败，释放占用并要求研究者重试，不生成虚假的模型调用凭据，也不把未完成工作投影为可继续结论。

## 主要依据

- 新增持久化建项前调查记录与哈希链测试，覆盖完整七步流程、重启恢复、顺序绑定、查询绑定、方向决定绑定和重复建项幂等。
- 新增统一前台动作契约及测试，覆盖工作台、用户简报、恢复、人工门禁、审查动作和版本冲突。
- 扩展 Agent 运行日志与服务测试，覆盖孤儿运行恢复、占用释放、失败投影和禁止伪造模型凭据。
- 扩展报告模型、工作台模型与 API 端到端测试，证明探索性预览不会升级为正式结论，旧状态不会在重启后覆盖当前科研判断。

## 科研与运行边界

- 当前自动化证明的是状态一致性、可追溯性和拒绝错误跃迁，不证明生成内容在任何医学领域都具备科学有效性。
- 大范围扫描仍以题名与摘要为主；摘要未报告保持未知，正式方法、数值、强因果或临床主张仍需少量关键全文核查。
- 低频主题不等于研究空白；候选综述方向仍需窄检索、同题综述比较、原始研究量核查与人工决定。
- 当前运行使用真实 Pi Agent 工具循环，但未配置在线模型提供商；可验证的是 guided 模式下的确定性执行，不是在线模型质量。
- 产品仍是本地、单研究者 Alpha，不应作为匿名公共多用户服务或医疗决策工具部署。
