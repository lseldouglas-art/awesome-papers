# v0.34：围绕题目与方案进行研判

状态：工程候选版。保留成果画布，优先改进选题判断与方案设计。真实模型质量对照和本人评价尚未通过，不以工程测试数量代替科研效果。

## 本轮行为

在候选题目的分析浮层中选择“与科研搭档核查本题”，侧栏绑定该题的准确版本。可以连续补充条件、核查反例或比较研究路线。初判先保存并显示，随后完整整理所选材料、审阅最可能改变推荐的问题，再形成修订判断。

初判只是阶段结果，其实际读取范围单独展示。所选材料的获取、完整处理与最终引用分别记录。仅使用已有材料是默认范围；可以明确允许按所选年份、类型和数量补查 PubMed。获取数量支持“全部”，不另设论文总数上限。决定性方法或数值需要时，可以允许核对一篇关键开放全文；普通扫描不要求全文。

新流程复用当前任务接口、来源访问快照、逐篇批处理、原文定位、版本与决定。没有另一套研究事实库。历史 AI 答案只用于接续工作；同题的用户纠正按照时间进入下一轮，不能变成文献事实。

方案可以保存为模型拟议草案，随后精确编辑或明确采用。用户可以直接输入“把主要结局改为 X，并采用这一版”。“可能改为 X”“是否应该修改”会继续讨论。自然语言动作只覆盖明确的单字段修改及采用；不能准确解析的复合表达保持讨论，不猜测执行范围。手工编辑仍可使用。

## 接口和记录

- `POST /api/projects/:id/research-tasks` 增加 `mode: question-investigation`，必须指定本课题真实存在的题目或方案及版本。
- `investigationOptions` 包含 `search: saved|pubmed`、补查时的既有 `retrievalOptions` 和可选 `allowFulltext`。服务端验证来源范围与实际版本。
- 原始 `task.input` 保持不变；`task.investigation.phases` 依次保存初判、质疑、修订的输出、引用、实际调用标识和时间。仅保存可审查解释，不索取隐藏思维链。
- 补查新增独立搜索与访问快照。重试继承原阶段和已完成批次，只处理剩余内容；服务中断、明确停止与晚到响应分别记录。
- `apply-research-proposal` 从任务实际输出保存草案，作者为模型。`research-partner-action` 只将直接用户指令适配到现有修改与采用命令。模型返回的操作指令没有权限。
- `create-quality-comparison` 和 `record-quality-review` 用已有事件记录实际输出的 A/B 比较与人工评价。版本名称在评价前隐藏，实际输入和配置仍可追溯。没有科学真实性总分。
- 实践路径支持工作台、GPT、Z Code 和自定义名称；实际模型、提示、反馈轮次及材料范围以用户记录为准。

## 验证边界

工程测试覆盖：本轮只查已选材料、额外反例进入后续阶段、初判不被回写、完整批次与批内有效记录复用、部分元数据失败后续取、同题纠正、跨范围引用与全文目标拒绝、旧题版本输出不覆盖当前内容、停止后晚到输出、模型草案身份、有限自然语言动作、质量评价及自定义路径。

浏览器使用隔离工程样例和模拟模型，验证桌面 1440×1000、手机 390×844、保留画布的侧栏、初判在处理期间可读、核查后建议、方案保存与明确采用、手机关闭返回画布。模拟响应只证明工程行为。

真实六个用例为：候选推荐、最近相关研究、最强反例、资源约束、研究设计取舍、纠正条件后的重新判断。旧、新流程分别在独立课题副本运行，防止新流程自动继承该组旧回答。保持模型与配置一致，实际输入范围和调用代价分别记录。当前只完成输入和历史回答冻结，没有取得新流程的真实质量改善证据。

三个核心用例——推荐理由、反例核查、方案取舍——得到具体改善证据并经本人认可后，才推广到领域理解、结果解释和正文修订。当前仍止于题目与方案研判。

## 复用与限制

复用 `research-application` 的任务、停止、调用与恢复，`workflows` 的批处理和引用定位，`continuity` 的版本和采用，既有 PubMed 规划／导入、开放全文服务和 UI 组件。无新增运行依赖。

首版一次只处理一个最值得核查的问题；更多问题在下一轮接续。它不会自动完成统计分析、实际实验、伦理审批或发表判断。来源定位验证只证明摘录来自实际快照，不证明摘录足以支持结论。真实质量、时间和成本需如实报告改善或未改善。
