# 请求恢复与本地性能优化 · v0.36.0

2026-09-22。接续 v0.35.0，仍处于单研究者实践与工程验证阶段。依据用户提供的“比较科研项目”最新审查及当前代码，优先处理发送阻塞、整库进度写入、局部答疑的大输入；保留 React、Node 和现有研究内核。

## 使用变化

- 发送后自动读取持久化请求回执。回执丢失、刷新页面或浏览器恢复时，查询只用 GET，不自动重发模型请求。确实未送达时保留输入，用户可以点“重新发送这条请求”，沿用同一请求编号。
- 在热点、分支上点“深入交流”，默认选择该内容引用且仍在本次选择中的材料，发送前显示篇数与边界。可切换为全部已选材料；完整领域分析、候选比较、专项研判的材料范围没有被偷偷缩小。局部追问不修改材料库或将用户目标改成写综述。
- 调用记录按需展开实际模型、运行方式、耗时、输入材料量与未知费用。SDK 内部真实请求数无法确认时显示未知，不再用任务记录数冒充物理调用次数。
- 无可用完整响应的新失败任务不再提供无法工作的本地重新校验按钮；不自动修补不完整科学结论。

## 性能与可靠性

任务进度、模型回执及新增事件在一个 SQLite 事务中定向保存，不再为每次进度变化重读和比较整库。回滚、跨课题保护、事件顺序和历史不可变规则保留。任务开始先返回回执，再安排工作；项目清单只读取元信息。

页面读取当前课题的任务摘要，保留判断、阶段、准确材料身份和恢复参数；大段请求上下文、摘要正文与逐篇整理不再随每次页面刷新重复传送。逐篇整理在展开时单独读取，完整数据库记录、历史版本与导出路径不变。单任务轮询继续使用 ETag，不重复建设既有缓存机制。

离线数据库副本的测量（十进制 MB；一次旧基线、三次新定向测量）：

| 指标 | 原实现 | 本版 |
|---|---:|---:|
| 保存一次任务进度 | 5,110 ms | 28 / 18 / 18 ms |
| 当前课题响应内容 | 204.90 MB | 26.10 MB |
| 当前课题摘要读取 | — | 601 / 583 / 595 ms |
| 新摘要任务读取 | — | 8 / 8 / 13 ms |

其他仍走通用事务的修改约 1,839 ms；不能据此声称所有写操作均为几十毫秒。以上仅是本机存储与载荷测量，不是模型推理或科研质量的提速证明。真实历史两次局部追问仍携带 631 份材料，单次模型耗时约 161 秒和 266 秒；本版为用户提供明确的局部范围，没有擅自降低最高思考档位。

候选比较的两个 SDK 入口补齐结构化输出合同，仍继续执行科学依据、维度和引用验证。SDK 初始化结束后重新检查取消信号，初始化期间取消不再启动新查询。传输容量、正文容量和生成截断分别报错，不用一个“非法响应”掩盖原因。新增本仓库 V2 CI 工作流，包含测试、构建和原生 SDK 离线 smoke；没有推送，未声称远程 CI 已执行。

- 417 项完整回归通过，生产构建通过；主包约 688 kB 的体积警告仍在。
- 安装的 SDK 原生进程对本机模拟服务通过，2 次模拟请求、1 次材料读取，真实外部模型调用 0。
- 浏览器桌面与 390px 手机验证：丢失回执自动恢复、刷新恢复、未送达后明确重发且编号相同、局部范围、调用记录按需读取，无页面异常或横向溢出。
- 上版浏览器回归通过：一级／二级／三级内容、证据独立折叠、重新生成候选回到画布、编辑微调并同步主页面、刷新保留。
- 新真实模型调用 0；没有将私人材料重新外发，没有替用户重新运行失败任务。结果的科学准确性、真实模型端到端提速仍需用户在正常研究中检验。
