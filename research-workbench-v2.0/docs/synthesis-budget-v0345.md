# v0.34.5：综合阶段生成额度

在大量逐篇记录已完整保存后，最高档领域综合仍可能用尽32,768生成tokens，正文却为空。此前程序对所有GLM请求写死32K，并未区分最高档综合与普通提取；此时不存在可修复的半份JSON，也不应重新提取全部文献。

本修复继续保留所选模型和思考档位：

- GLM-5.3-Flash最高档领域／专题综合的自动额度为65,536，其余请求仍为32,768；已有显式输出额度优先。
- 本机设置的“服务商的材料处理能力”可填写输出额度，范围依据[智谱官方模型文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)公布的128K上限。此配置确实传至模型请求，不只是上下文规划参数。
- 对应等待上限随额度调整：自动64K配置最长24分钟，可立即停止。额度是上限，并不要求生成满；更大额度可能增加时间与费用，不能称为速度优化。
- 任务在调用前保存实际生成额度；失败响应保留实际请求参数、用量和结束原因，不保存或展示隐藏推理。
- 生成额度用尽且没有正文时，给出明确原因。完整逐篇记录继续通过原接续路径复用，只重新综合。
- 其他供应商、未知模型不套用GLM专用参数，不自动降档，也不自动重发失败请求。

验证：393项隔离回归、生产构建通过。新增重现零正文耗尽额度、最高档综合与普通提取额度区分、显式覆盖、等待边界、供应商隔离及额度持久保存。桌面1365×1000与手机390×844验证输出额度保存；合成配置关闭模型服务，无真实模型测试调用。

64K是修复32K硬编码后的默认运行额度，不能保证每次最高档大规模综合都成功。实际端到端速度、费用与科学内容质量需按真实返回记录，不能由模拟测试代替。
