# 科研工作台 v0.34.6 使用说明

依据：v0.34.6实际实现，核对日期2026-09-21。配套阅读：[架构介绍](architecture-v0346.md)、[本轮审查与已知限制](green-review-v0346.md)。

工作台用于持续组织一个课题的目标、材料、判断、方案、真实记录和写作。你可以停在领域认识、选题比较或研究方案，也可以继续到正文和图稿。它目前是生物医学资料连接较完善的本机单研究者产品，科研判断仍需研究者核对。

## 1. 当前能做什么

| 工作 | 你提供什么 | 工作台交付什么 | 边界 |
|---|---|---|---|
| 明确研究起点 | 当前想法、经验、资源和期限 | 研究画像、起步安排 | 目前新课题仍进入统一画像与领域入口，不是任意文件一键接管已有项目 |
| 领域认识 | 领域问题、检索范围、选定材料 | 领域概览、七维分析、逐篇记录、图解 | 材料内认识，不代表完整学科综述 |
| 候选比较 | 研究目的、类型与不满意点 | 候选问题、拟议设计、价值及条件估计 | 创新性、周期、难度是待核对判断 |
| 选题与方案研判 | 当前题目或方案、具体疑问、核查范围 | 初判、关键质疑、补查发现、修订判断、方案草案 | 一轮围绕一个最可能改变决定的问题，不自动运行整项研究 |
| 专题文献库 | 已选题目、专题检索式、纳排意图 | 校准、收集、相关性建议、主题分类、人工纳排 | 当前直接检索主要是PubMed，不能承诺跨数据库完整召回 |
| 研究方案 | 问题、证据、方法与现实条件 | 可编辑方案、采用版、历史与影响记录 | 方案生成不等于实验执行 |
| 接回外部结果 | 实际执行过程、结果正文、附件 | 执行记录、结果解释、工作建议 | 不自动运行统计、实验、招募或伦理流程 |
| 大纲与写作 | 核心材料、研究问题、确认的大纲 | 论证大纲、中文或英文初稿、逐节及逐段修订 | 不能虚构本研究结果，初稿需要审阅 |
| 模板全文精读 | 已选择的参考论文、取得的原文 | 并排阅读、结构分析、段落修改建议 | PDF文本解析不等于原图、表格和科学结论全部核验 |
| 科研图稿 | 真实数据、步骤或已有文字关系 | 柱状图、折线图、流程图、可编辑示意图 | 不自动推断显著性、置信区间或生成实验结果 |
| 历史、导出与对照 | 选定版本、评价理由 | 成果与依据包、恢复记录、A/B质量比较 | 导出包不等于整个工作区备份 |

## 2. 打开页面与认识布局

当前本机使用地址是 `http://127.0.0.1:4320/`。服务已经运行时直接打开；新版本提示出现时先保存当前输入，再使用“保存并更新界面”。顶部小版本号用于确认界面代码版本。

| 位置 | 用法 |
|---|---|
| 左侧导航 | 新建课题、我的课题、研究进展、本机模型与说明 |
| 研究脉络 | 返回领域认识、候选比较或某一题目的探索页；保留来路 |
| 中央成果画布 | 阅读报告、题目、大纲、正文和图稿；这里是当前讨论对象 |
| 本页大纲 | 跳到当前成果的相应章节 |
| 顶部“大纲／批注／交流” | 展开辅助内容；窄屏可以收起，留出阅读空间 |
| 页面上方“当前课题” | 查看当前依据与未决，进入“方案与研究记录” |
| 底部输入框 | 围绕当前内容提问、提出修改或记录想法 |
| 输入框下方材料数量 | 调整本次发送给模型的材料范围 |
| 思考控件 | 选择下一次新任务的模型思考档位 |

不同阶段显示不同入口。已保存的专题、正文和图稿从所属研究脉络接续，不需要每次重建课题。

## 3. 从一句想法建立课题

1. 点击“新建课题”，在首页输入当前目标。先写这一轮要得到什么。
2. 点击“建立课题”。这一步创建本机课题，不表示文献已经检索或模型已经完成研究。
3. 依次记录领域基础、近期目标、研究背景、能力与协作、可用资源、时间与成果要求、约束与资料边界。
4. 不知道的内容可以留为未知；不要为了填完整而声称有病例、设备或统计支持。
5. 核对后点击“确认画像与起步计划”，进入研究页面。以后可通过“核对或调整我的现状”更新。

示例输入：

> 我想了解某疾病的某类治疗研究，先弄清主要问题、证据分歧和可写综述的方向。我目前没有临床数据，能够做文献研究，预期三个月形成初稿。

如果近期只想了解领域，就直接写“本轮只形成领域认识，先不选题”。领域理解可以独立完成，不自动升级为综述写作。

## 4. 领域认识：先取得材料，再整理与综合

页面将过程分成“范围与检索式 → 查看与筛选文献 → 理解与反馈”。

1. 查看系统给出的范围说明和PubMed检索式。可以编辑检索式，或讨论范围是否太宽、太窄。
2. 在“直接选择文献获取范围”选择时间、文献类型、数量和排序。可以选择“范围内全部”；不要把默认近五年误认为全部历史。
3. 开始获取题名与摘要。这里主要是数据库访问，不等于已调用模型逐篇分析。
4. 在“查看与筛选文献”核对题名、摘要和实际访问层级，排除与本轮问题无关的材料。新检索结果默认选中，发送前应确认范围。
5. 查看分析设置，启动本步分析。
6. 等待时可打开已保存批次。提取完成后仍需综合阶段，进度不应只看一个总百分比。

逐篇记录包含五项：研究对象与问题、方法概述、主要发现、与当前课题的关系、摘要未报告与局限。

领域报告包含概览和后续方向，中间七个维度是：领域历史、主要分支与发现、当前热点、关键争议、技术与方法演进、证据空缺与未知、研究成熟度。材料不足的维度应说明不足，不能凭空补全。

图解用于辅助阅读，完整文字和来源仍可展开。点击“查看依据”或具体引用，可以回到当时保存的题名、摘要或原文片段。

已有外部资料时，点击“补充参考材料”，填写题名、实际提供范围和文本，保存并关联。它会标为“你提供的内容 · 未核验”；发送前再在本次材料范围中选择。这个入口不会替你取得尚未提供的原文。

必须区分四个数量：**已取得、已完整整理、报告实际引用、经过人工核查**。例如631篇整理完成，不能解释为631篇全文已读，更不能解释为631项科学结论已验证。

## 5. 不满意选题，怎样重新生成

在“领域认识”或“选题比较”页面使用底部输入框。若已进入某一题目的独立探索页，先沿研究脉络返回“选题比较”，更容易准确表达要更换整组候选。

可直接输入：

> 我想写一篇综述，当前候选不符合我的需要。请重新推荐几个可以通过文献综合回答的问题，说明综述类型、具体边界、最接近综述已经做了什么，以及本题增量还需要怎样核查。我的资源条件沿用已确认画像。

识别成功后，输入区会显示重新生成候选的提示。也可使用输入区的“重新推荐候选选题”模式明确指定动作。若只出现普通答疑，不要反复提交相同长请求，先核对当前页面和动作。

当前已接入明确的综述重新选题意图：综述候选应围绕文献综合，不应把新临床队列或Delphi共识直接当作你的综述任务。更新候选保留旧版本和原有取舍；“重新推荐”本身不自动采用新题目。

候选图表可比较可行性、潜在创新、投入价值、执行难度及周期。星级和月份都依赖资源假设，周期到初稿、不含审稿。悬停快速查看，点击固定阅读，再打开“查看本题的完整分析”。

## 6. 深入核查一个题目或方案

进入某题完整分析，点击“与科研搭档核查本题”；方案字段也可以点击“讨论这项”。确认侧栏显示的是当前对象和准确版本。

1. 输入具体疑问，或点击快捷问题填入输入框；快捷问题需要再发送。
2. 展开材料范围，选择“仅查本次所选材料”，或“先查所选材料，再按需补查PubMed”。
3. 允许补查时设置年份、文献类型和数量。关键方法或数值需要时，可单独允许读取一篇关键开放全文。
4. 选择思考档位，点击“给出初判并核查”。
5. 先阅读阶段初判；后台完整处理所选材料，提出关键质疑，按范围补查，最后形成修订判断。
6. 查看建议为何改变、还有什么未知、哪些条件可能推翻推荐。需要下一轮时补充条件或问题，继续同一对象。

适合的提问：

- “结合我的条件，这个题到底值不值得做？”
- “找出最强反例，核查后更新建议。”
- “比较最小可行方案与更强证据方案。”
- “我没有病例数据，只有文献和公开数据，请重新判断可行性。”

初判只依据当时已处理的部分，不等于最终结论。“本轮过程与实际范围”保留之前阶段、专项检索、访问层级与调用信息。后续阶段的处理量和引用量分开显示。

这是一次有界研判；不是输入一句话就连续自动执行全部科研。当前通用研判主要围绕题目和方案，尚未推广为所有研究阶段的自由Agent。

## 7. 建立与筛选专题文献库

题目收敛后，从题目页进入“专题文献库”。

1. 查看围绕本题的检索式，先做前20篇校准。相关文献太少或偏题，可使用对应入口修改。
2. 手动编辑的检索式保留；新建议生成后，选择需要的建议，再重新校准。
3. 设置收集年份、排序和数量，开始分批收集。获取未完成时可继续取得剩余文献。
4. 进入阅读与筛选。按相关性、主题、关键词和取舍过滤，逐篇阅读摘要。
5. 使用“纳入并看下一篇”“排除并看下一篇”“暂留，下一篇”；需要时记下理由。也可批量纳排或应用等级范围。
6. 核对机器分类，可修改相关性、关键发现与两级主题。机器建议和你的最终纳排分别保存。
7. 点击“用这些文献”接续后续研究；可以深入论证已有证据、缺口和设计，或进入大纲。

A/B/C/D分别是直接相关、间接相关、稍微相关、不相关，**不代表研究质量、证据等级或自动纳入决定**。前20篇校准是检索反馈，不是召回率评估。

文献列表支持固定预览、上一篇／下一篇、分页，以及列表区域的J/K切换。纳排操作不删除原始文献，历史取舍仍保留。

Zotero接口用于连接本机Zotero、定位已有条目、打开条目或PDF、读取可取得的附件文字。RIS导出用于你自行导入Zotero。当前不是全库自动同步或双向回写工具；查不到条目也不代表文献不存在。

## 8. 保存、讨论与采用研究方案

从“方案与研究记录”进入“研究方案”。可以从已有论证整理草案，也可编辑研判产生的方案。

方案包括：研究问题、本轮目标、研究路线与方法、主要结局／核心比较、次要结局、分析单位、结局单位、分析或综合方法、材料与数据需求、范围与纳排标准、限制与未知、下一项工作。

文献研究不必强填不适用的实验字段。不知道的方法条件、效应量和样本量依据保留未知。

**保存草案**保留内容和版本；**采用这版方案**确定后续研究依据。修改草案后，当前采用的旧版仍然有效，直到你明确采用另一版。也可以保留、不采用或保持未决。

在具体方案的科研搭档中，当前支持部分明确自然语言动作，例如“把主要结局改为X，并采用这一版”。“是否应该改成X”保持讨论。此能力有对象和语义范围限制，不是任意长指令都能准确执行；多字段复杂修改可使用表单并检查保存结果。

查看“保存历史”可打开旧版，“恢复为新的草案”会新增记录，保留中间历史。

## 9. 外部执行、结果与建议怎样接回来

在“方案与研究记录 → 执行与结果”选择记录类型：执行与结果、结果解释、外部建议或附件。

记录实际结果时，尽量填写执行者、时间、实际方法或代码、关键参数、工具版本、与方案的偏离、局限及下一步。实验尚未做完就记为部分完成；外部AI给出的内容选择外部AI建议，不能记作已经发生的实验。

当前可保存TXT、Markdown、CSV、JSON、PDF、PNG、JPEG附件，通用研究附件单个不超过24MB。**附件保存用于追溯，不代表模型已经解析或看过附件**。需要模型解释的具体数值与发现，应写入记录正文；模板PDF另有专门读取入口。

点击“用于后续工作”选择实际要接续的结果，再用“带着当前依据继续讨论”分析其含义和限制。工作台可以帮助讨论结果，不会在后台自动运行R、Python、SPSS或实验设备。

方案或结果改变后，打开“影响与核对”，定位已有依赖关联的下游成果。核对后可以记录“仍适用”“稍后处理”或“已更新相关内容”。旧稿没有记录依赖的部分，不能据此认定全部一致。

## 10. 大纲、初稿、模板阅读和修订

1. 在专题核心材料基础上生成“研究大纲”。查看每节中心命题、论证推进、相反解释、关联材料、图表计划与待补条件。
2. 调整论证或章节，满意后点击“确认并开始写作”。
3. 在“完整初稿”选择中文或英文，生成初稿。系统按小节生成与保存，显示已完成节数；中断后可继续。
4. 阅读完整初稿，再选择并阅读模板文献。
5. 在“逐段审阅”中核对句子来源、编辑正文、保存新版本，并查看哪些段落仍有待核对事项。

写作可以选择文献论述、拟议方案或真实结果等用途。后者必须接入实际已有的本研究记录，不能把外部文献数字写成自己的结果。

模板支持已有文献选择、候选推荐、粘贴原文或片段、开放全文获取、PDF导入及Zotero附件文字。模板PDF入口单个文件上限25MB，与通用附件入口不同。

PDF阅读器支持分页、缩放、文字搜索和原文定位。需要时人工确认PDF包含完整正文。只有摘要时，认识必须限定在摘要；扫描件、复杂版式和提取失败需要人工补充，不保证OCR或表格结构完整。

完整原文分析后，可以并排精读，选择写法参照，再提出逐段修改建议。学习的是论证与表达方式，不能迁移范文的研究事实。部分深化入口要在当前正文完成审阅、模板读取条件满足后才开放。重点章节包括引言、讨论、摘要与关键词；摘要采用后才进入正文导出。

## 11. 科研作图

“科研作图／图像工作区”提供两种工作：

**数据图与流程图**：选择柱状图、折线图或流程图。数据输入首行是`label,value`，每行一个标签和数值；也可导入CSV。流程图每行一个真实步骤。补齐图题、单位、图注与来源后保存、导出SVG或PNG。它不执行统计检验，不自动计算误差线、置信区间或Meta分析。

**可编辑示意图**：从素材库添加素材、文字、区室和连线，调整颜色、布局及关系。可带入已存正文，让当前文字模型“整理关系并提出排版”，再选择是否应用到画布。每条关系可记录依据，素材有作者与许可记录。

手工作图不需要模型调用。文字关系整理会发送本图文字、专题名称和素材目录；它不是文生图模型直接生成实验图像。可导出可编辑SVG、PNG、图稿结构及图注署名。按印刷宽度导出像素不代表原始素材已经满足期刊清晰度要求。

## 12. 模型设置与长任务

在“本机模型与说明”配置服务地址、模型名和密钥。配置保存不等于测试；“测试连接（1次）”会实际调用服务。

| 设置 | 当前作用 |
|---|---|
| 输入框思考档位 | 下一次新任务的档位；已运行任务保持原设置 |
| GLM-5.3-Flash档位 | 本实现已接入低、高、最高；其他未核对模型只显示默认 |
| 每批整理篇数 | 默认计划50篇；输入或输出能力不足时可拆成更小实际调用 |
| 同时整理批数 | 默认2，可设置1–4；受服务商并发额度限制 |
| 逐篇整理思考档位 | 可跟随任务，也可单独设置；最终综合仍使用任务档位 |
| 单次实际输入额度 | 仅在确认服务商能力时填写，用于完整分批规划 |
| 单次输出额度 | 已识别GLM的最高档领域／专题综合自动64K，其余自动32K，显式配置优先 |

批次大小和并发设置用于下一次开始或接续，运行中的任务不会动态改变。失败接续保留原任务模型与主档位；若要换研究条件、模型或主档位，按界面提示新建一轮，保留可解释的对照。

“最高”表示思考设置，不是更好的科研模型，也不保证更快或更准确。想比较低档提取是否足够，应核对同一批实际材料的提取质量，不能仅看速度。本说明不会替你更换当前设置。

50篇是逻辑批次目标，不保证一批只调用一次模型。容量拆分、提取、综合和研判阶段各自可能有调用。材料处理、模型生成、来源检查和保存也有不同耗时。

文献格式或覆盖错误有最多一次的自动补救；输出容量不足会拆分剩余材料，保留已完成记录。网络与服务错误不会自动反复重发。因此，逻辑批次数、实际模型调用数和已保存记录数可能不同。

任务上方显示本轮已运行时间和当前模型请求用时。可以先读已保存批次；全部提取完成仍需等待综合。自动64K配置单次等待上限24分钟，不是预计完成时间。

## 13. 卡住、失败或需要停止时

| 现象 | 建议动作 | 会保留什么 |
|---|---|---|
| 部分批次完成，后面失败 | 查看原因；范围未变时继续未完成部分 | 已保存的合格材料整理 |
| 全部材料完成，最后综合失败 | 接续综合，先检查模型输出原因 | 已完整整理的记录 |
| 提示完整输出可重新校验 | 使用“重新校验已保存输出” | 原响应、原失败及独立恢复记录；合格时不需新模型调用 |
| 引文与原文不符 | 查看来源，继续核查问题阶段 | 原回答继续保持未通过，不自动改写引文 |
| 研究条件已经改变 | 开新一轮，解释具体更正 | 旧任务及旧输入版本 |
| 不想继续等待 | 点击“停止”，等待状态确认 | 已完成工作；晚到输出按取消规则处理 |
| 开始请求状态不明 | 先点“确认上次请求状态” | 未确认输入；避免重复开始 |
| 出现保存冲突 | 对照当前已保存内容与自己的输入 | 两份内容；确认后保存新的版本 |
| 无法连接工作台 | 检查本机后台服务、端口和电脑状态 | 服务已确认保存的数据仍在本机 |

关闭标签页不等于停止后台任务；电脑睡眠、网络中断或后台服务退出可能中断任务。恢复页面不会自动重发所有失败模型请求。“继续”可以产生新的服务调用；已经失败的调用可能仍有供应商用量。

v0.34.6在修改报告时能复用当前报告或准确来路中的合格材料记录，但来源文本、访问层级、模型或必要背景改变时，复用范围会缩小。明确要求重新逐篇核对时仍会重新提取。

## 14. 保存、导出、备份与隐私

日常个人记录与草稿按各入口自动保存；有“保存”或“采用”按钮的动作应以页面反馈为准。未发送输入和部分未提交草稿还会暂存在浏览器，清除浏览器数据可能丢失这些临时内容。

“保留当前进展”用于留下一份便于回看的阶段记录。“研究进展”用于查看旧版与恢复；恢复形成新记录，不删除中间历史，也不自动改变科学采用决定。

| 导出入口 | 内容 |
|---|---|
| 领域／成果页导出 | 对应页面或所选历史版本的内容及记录，以入口标明格式为准 |
| 正文`.md` | 可继续编辑的Markdown正文 |
| 正文排版稿 | HTML阅读稿；不是原生Word排版系统 |
| RIS | 已选文献题录及实际取得的摘要，用于文献管理器 |
| 图稿 | SVG、PNG及图稿结构等 |
| 成果与依据ZIP | 当时显示的成果文件与依据、版本清单；不保证包含所有原始附件二进制 |
| 同题实践记录 | 工作方式、实际条件与使用反馈 |

导出忠于选定版本，不额外调用模型润色。当前没有一键导出完整期刊格式DOCX的承诺。

项目主要存储在本机SQLite数据库，PDF和研究附件还在数据目录的子目录中；模型密钥在独立私有配置文件。**本机保存不等于完全离线**：启动科研任务会把相应背景与选定资料发往配置的模型服务，PubMed检索会发送检索式，开放全文获取会访问对应来源。

完整备份应包含一致数据库副本及所需附件目录；有运行中写入时不要只复制一个`.sqlite`文件当作完整热备份。恢复应先停止该数据目录的服务，在新目录验证备份，不覆盖现有工作区。密钥配置另外保管，成果导出不能恢复所有设置。

## 15. 与GPT、Z Code等工作方式对照

在“方案与研究记录 → 实践记录”选择工作路径，记录实际模型、提示、材料范围、反馈轮次，以及卡在哪里、怎样继续。支持科研工作台、GPT、Z Code和自定义名称；它记录你的实践，不会自动登录或操纵外部产品。

在科研搭档中打开“比较研究质量”，选择已保存输出，隐藏版本名称后比较A/B，再记录偏好、理由、质量维度和问题归因。不同模型、材料或提示造成的差异需要单独解释。

六类用例：候选推荐、最接近研究、最强反例、现实条件、设计取舍、纠正条件后的判断。重点看是否帮助你作出更好的研究决定，不以字数、引用量或测试数量评判。

## 16. 两条完整操作路径

**文献综述**：建立课题并说明综述目标 → 理解领域 → 明确要求生成综述候选 → 围绕某题核查相近综述与增量 → 选择题目 → 专题检索与人工筛选 → 比较证据与确定综合方法 → 保存并采用方案 → 生成并确认大纲 → 形成初稿 → 模板精读和逐段核查 → 图表与指定版本导出。

**原始研究**：理解领域与核查问题 → 形成并采用方案 → 在外部完成获准的实际研究／统计 → 把真实过程与结果接回 → 核查结果解释和方案偏离 → 用真实结果支持大纲、正文与图表。

这两条是使用路径，不是强制从头重跑的流水线。已有成果可以从所属页面接续；还没有专门导入器的外部内容，通过材料、方案或记录入口明确接入。

## 17. 当前仍未实现或未充分验证

没有通用Python/R科学计算内核、自动实验执行、多用户协作权限、全学科数据库连接、自动投稿或发表预测。不能以已有表格、方案字段或提示词中出现GRADE、PRISMA等术语，推定正式方法学工作已经完成。

Claude Agent SDK有受控试点接口，但默认关闭，尚未证明真实供应商兼容和科研输出优于常规路径。科研搭档也不是完整Claude Code终端。

v0.34.6已有403项工程回归及本机界面验证；真实六组科研质量对照和研究者评价尚未完成。引用精确定位证明文本来自保存的来源，不证明它足以支撑旁边的科学结论。

首次使用最值得完成的一件事是：选定一个候选，结合真实条件做一次研判，核查相反证据，最后明确采用、缩小还是保留未决。
