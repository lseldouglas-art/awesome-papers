# v0.35.0：交流结果回到选题，领域内容逐层阅读

当前仍处于单研究者同题实践阶段。主画布保留研究对象，侧栏交流用于提出和核查修改；领域认识不默认导向综述写作。

## 使用方式

- 单题页面点击「交流并微调」。讨论形成建议后可编辑名称、研究问题和范围，点「更新当前选题」同步本页及仍包含此题的原候选比较。也可直接微调已有题目。旧讨论、旧报告和已采用版本保留；原问题或范围改变时，原价值、难度、周期与设计需重新核查。
- 候选比较点击「调整这批选题 / 换一批」，在下方说明反馈后发送。明确的「换一批」「重新推荐」也可直接在聊天中提出；新比较沿用原页面，原批次留在历史中。未要求重选的解释性提问继续作为交流。
- 热点按一级热点、二级热点、具体问题阅读；分支按分支、子分支、具体发现阅读。点击左侧主题切换，点击子标题展开内容。证据独立折叠，展开后才渲染原文与来源。
- 旧报告展示已有完整解释和明确保存的图解信息，不从文献数量或关键词编造二级层次。下一次用户更新领域认识时，新合同要求逐层解释对象、问题、发现、适用条件与未知；每个子主张独立校验引用。完整文字阅读和Markdown导出也保留子内容。

## 验证及边界

409项完整回归通过；最终细节调整后26项针对性复核通过；生产构建通过。隔离浏览器使用模拟模型，验证1440×1050桌面及390×844手机：一级切换、键盘展开二/三级、来源独立折叠、聊天换题、建议编辑、主画布保存、刷新持久化；页面异常0，手机横向溢出0。没有新真实模型调用，没有将私人材料重新发送给模型。工程验证不能替代对子层次科学解释的真实质量评价。

本机4320已运行v0.35.0。部署前全部任务空闲并备份SQLite；切换前后10表完全一致，模型配置不变，完整性检查ok。构建仍有既有主包体积警告，未为本轮引入新依赖。

下一项：用户在原课题用新的交流入口微调一题，或主动更新领域认识，审阅实际生成的子方向及其引用。当前已保存报告不会被模型自动重写。
