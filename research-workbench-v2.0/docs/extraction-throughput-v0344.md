# v0.34.4：文献逐篇整理提速

大量文献整理此前按批串行执行，最终综合所选的最高思考档位也用于每次事实提取。输出容量不足会拆分批次；子批已经保存时，页面仍等父批完成才更新篇数，且父、子记录重复出现在可读清单中。这些因素分别增加实际耗时和等待中的不确定感。

## 本次行为

- 复用现有批次执行器，领域理解、领域修订和专题分析默认最多同时处理两批独立材料。设置可选 1–4，需符合服务商实际并发额度；总材料范围不变。
- 运行失败立即停止派发新批；已在途请求完成后保存可用结果，再结束任务。取消仍丢弃晚到结果。拆分批次在发起下一次物理调用前也检查是否已有其他批失败，不持续追加请求。
- 所有批次保持“先保存意图、再调用、再校验与保存”的顺序；最终结果按计划顺序合并。只有覆盖全部选定访问文本后才进入综合。
- 每个校验通过的子批立即更新完整篇数，去除父子记录重复计数与阅读展示。长文献分段仍须完整覆盖才计作一篇完成。
- 将逐篇整理档位与综合档位分开配置。默认跟随本次任务，不自动降低旧配置；用户可选择逐篇低档、综合最高档。每个实际调用记录使用档位，任务记录两阶段设置。
- 分批、并行和逐篇档位在任务开始时固定；改变设置对下一次开始或接续生效。接续继续沿用原研究问题、材料及综合档位，保存新接续任务实际采用的提取设置，已完成篇目不重新处理。
- 运行中的界面不再用静态“预计批数”冒充实际剩余工作量。设置提示明确区分提取与综合。

没有引入新的 Agent 框架、状态库或服务依赖；使用原材料访问快照、引用校验、版本与停止接续机制。

## 验证

- 390 项隔离回归及生产构建通过。新增验证包含并行上限、乱序返回后的有序合并、首错后停止派发、在途成果保留、取消晚到输出、子批进度、去重和两阶段实际模型档位记录。
- 调度模拟：8 个等延迟请求，每次约 80ms。串行 658ms，双批并行 331ms，请求数和输出数均为 8，等待缩短约 50%。这是调度模拟，不是六百篇真实科研质量或端到端耗时承诺；服务限流、单次模型延迟、拆批及最后综合会影响真实速度。
- 隔离页面在桌面 1365×1000、手机 390×844 验证配置保存、档位独立和无横向溢出，未见页面错误。使用假密钥且禁用服务，模型调用为零。
- 提取低档的科学内容质量尚需实际使用核查；不能把更多 token 或更高档位等同于更高质量，也不能宣称低档质量已经与最高档等价。

模型档位依据发布方的 [GLM-5.3-Flash 说明](https://huggingface.co/zai-org/GLM-5.3-Flash/blob/main/README.md)：支持 low、high、max。保留当前服务商、模型和完整材料范围，未知费用仍记为未知。
