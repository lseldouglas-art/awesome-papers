# v0.34.2：输出恢复与引用契约

本轮遵循 Ponytail：复用现有调用记录、逐篇整理、材料覆盖、版本与接续机制，不迁移语言或引入第二套研究状态。

## 改动

- 流式回答中断或输出容量耗尽时，保存已经收到的回答正文、结束原因和服务商实际返回的用量。未完成输出仍不作为成果；不保存隐藏思维链或服务商错误响应正文。
- 从不完整批次中保留已完整解析、通过字段和原文定位校验的单篇记录。支持紧凑 JSON；不猜补括号、引号、数字或科研事实。
- 明确的输出容量耗尽会拆分剩余材料，并记住较小的调用规模。断网、超时、限流不自动重发；已取得的合格内容供用户接续。格式错误仅有界补救。
- 同一套提取恢复逻辑供领域整理与选题研判复用。材料总范围和覆盖门槛不变，每次整理篇数可设为任意正整数。
- 研判提示统一要求真实 R/P 编号。历史输出把原文写入 passage 时，仅允许在指定快照内唯一、精确匹配，并保留转换记录；省略号、模糊摘录、未知 P 编号和跨来源引用仍拒绝。
- 为逐篇整理和三阶段研判建立版本化 JSON Schema。Ajv 不修改或补全字段；原始输出先保存，结构校验不能代替引用和科学判断校验。已知 GLM 服务沿用 JSON object 模式，不假定其他供应商支持严格 schema。

## 验证与边界

完整隔离回归 374 项通过；追加回答截断与用量保存测试后，模型适配器 26 项通过。生产构建通过。测试均用合成材料和模型桩，不重新发送私人课题材料。

涵盖完整覆盖、局部成功后失败、取消后的晚到输出、紧凑 JSON 截断、历史摘录兼容、未知来源拒绝及旧项目兼容。未进行真实供应商长批次测试或科研质量评价；恢复成功不代表科研结论成立。

## 复用依据

采用 [Ajv](https://github.com/ajv-validator/ajv) 的声明式结构校验（MIT）；保留项目现有研究内核。供应商 JSON 模式依照[智谱官方说明](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output)使用，未扩展其他服务商权限。
