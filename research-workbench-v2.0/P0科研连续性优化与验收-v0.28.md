# P0 科研连续性优化与验收 · v0.28.0

日期：2026-09-12 至 2026-09-13。状态：**三个批次的开发与工程验收完成，本机已升级；等待研究者连续体验后进入同题对照实践。**

## 本轮解决的问题

原工作台已经能进行领域认识、专题建库、大纲、写作、精读和作图，但研究者仍需自己连接“现在采用哪版方案、外部实际做了什么、下一次任务使用什么、上游变化影响哪些成果”。本轮按用户批准的 P0 计划补上这些连接，复用既有研究对象、版本、决定、任务、依赖与 SQLite，不建设第二套项目状态系统。

现在可以在同一课题中采用一版方案，带着准确版本讨论或写作，接回外部执行记录与附件，再沿实际依赖处理变更、查看旧版并导出当时的成果与依据。保存草案、采用方案、实际执行、模型解释分别保留；用户继续拥有研究判断。

## 三个批次的交付

| 批次 | 已实现行为 | 可直接体验的例子 |
|---|---|---|
| 第一批：当前课题与采用方案 | 当前问题、采用内容、未知与下一步的只读汇总；轻量方案字段、自动保存历史、明确采用；真实任务进度与已保存批次；主线隔离、重开接续 | 采用第 1 版后修改草案，第 1 版继续用于研究；再次打开可查看准确采用版，导航不会触发模型 |
| 第二批：外部结果与变更接续 | 分开保存外部建议、实际执行、结果解释；记录执行人、时间、方法、环境、偏离及文件；任务使用准确输入；写作用途明确；变更传播至实际依赖的大纲、正文与图稿 | 用已有统计工具或 Codex 完成工作，把真实输出接回；修改主要结局后，查看涉及旧版本的成果并逐项保留、暂缓或更新 |
| 第三批：忠实导出与实践准备 | 页面指定版成果和独立依据清单打包；不可变历史恢复；文件完整性与缺失说明；同题实践简记；异常回归、浏览器验收、两条公开材料预演及本机升级 | 导出旧方案仍保留旧结局；关闭重开后继续；记录在工作台或 GPT 路径上卡在哪里、如何补救，不预设比较胜负 |

第一批对应批准计划 A+B，第二批对应 C+D+E，第三批完成导出、排练、修复与版本冻结。计划中的“本人连续体验”需要研究者实际使用，不能由工程验收代替；这一项尚未完成。

## 交互与使用方式

1. 打开已有课题，在“当前课题”查看下一项工作，进入“方案与研究记录”。系统用已有内容预填候选，单纯打开不会保存或采用。
2. 在“研究方案”中说明问题、设计、结局、分析单位、分析计划和实际限制。可以留空未知项，编辑自动保存历史；需要用于后续研究时选择“采用这版方案”。
3. 在“执行与结果”中选择实际记录类别。外部 AI 的建议归入建议或解释；实际执行记录说明谁、何时、用什么方法做了什么，可以记录失败或部分完成。
4. 通过“所用版本与附件”关联当时使用的方案和文件，选择哪版结果用于后续工作。附件用于保存和追溯；需要模型讨论的实际内容写入记录正文，不默认把任意附件全部解析给模型。
5. 研究讨论、大纲和正文承接准确输入。正文显式选择文献论述、研究方案或真实结果用途；没有真实结果时不应把计划或文献中的数值写成本研究观察。
6. 在“影响与核对”定位受变更影响的成果，前往原位置核对。系统给出的结局角色或单位冲突只是待判断线索；用户决定仍适用、暂缓还是关联新的已更新版本。
7. “成果与依据 · ZIP”导出干净成果与单独的“依据与版本.json”。现有普通导出仍可使用。历史版本恢复为新的草案，原历史及采用决定不被覆盖。

窄屏沿用同一操作，四个标签在 390px 下完整显示；常驻课题区保持简短，具体字段在原生弹窗内按需展开。保存期间锁定该表单，避免网络等待时发生不明确的并发编辑；保存冲突保留本机输入，并提供服务端当前版与自己的输入对照。

## Ponytail：借鉴机制，复用已有组件

采用批准计划中已经核对的官方产品机制：方案与当前版本分开、执行记录保留过程、证据可回看、成果导出伴随依据。相关参考包括 [OSF Registrations](https://help.osf.io/article/330-welcome-to-registrations)、[protocols.io](https://www.protocols.io/)、[eLabFTW 实验记录](https://doc.elabftw.net/docs/usage/user-guide/experiments/)、[scite 引文核对](https://scite.ai/blog/how-do-i-use-the-scite-reference-check) 和 [Zotero 报告](https://www.zotero.org/support/reports)。这些是机制参考，未复制专有代码，也没有声称已达到这些产品的完整能力。

实际复用原 Modal、表单、来源抽屉、任务恢复、版本库、人工决定、依赖边、正文审阅、SVG/图稿能力。新增代码主要是既有对象上的规则与界面投影、文件完整性存储及轻量 ZIP 导出；**新增运行依赖为 0**。不增加独立数据库、电子实验记录平台、统计执行环境、多代理系统或每阶段审批关卡。

## 底层实现与准确性

| 位置 | 作用 |
|---|---|
| `shared/research-continuity.mjs` | 当前研究安排、准确版本引用、任务输入快照、实际记录选择、变更与文字冲突线索 |
| `demo-api/src/continuity.mjs` | 保存、采用、恢复、附件登记、实践记录与指定版本依据清单 |
| `demo-api/src/research-files.mjs` | 内容寻址、本地原附件保存、格式检查、SHA-256 校验、缺失显式报告 |
| `demo-api/src/kernel.mjs` | 复用内核与依赖传播，支持大纲、正文、图稿等内部版本的受影响定位 |
| `research-application.mjs`、`research.mjs`、写作相关模块 | 保存任务开始时的输入；只讨论所选真实记录；迟到输出保留为候选，不替换较新的采用状态或当前稿 |
| `demo-app/src/ResearchContinuity.jsx` | 课题简报、方案与记录、历史、影响核对、实践日志及草稿恢复 |
| `demo-app/src/ExportEvidence.jsx`、`shared/export-bundle.mjs` | 冻结点击时的输出和版本，打包干净成果与依据清单 |

明确版本引用不能回退成“最新版本”。旧稿没有保存的来源关系标为未知，不事后伪造。已采用解释不会自动成为原始观察；解释引用实际执行记录时，保留执行人的归属。只有引用确实出现在所选记录的对应字段中才通过位置检查，原句存在不等于科学主张成立。

文件目前支持 TXT、Markdown、CSV、JSON、PDF、PNG、JPEG，最大 24MB；不执行上传代码。不完整或缺失的文件不会悄悄替换为另一份；导出保留元信息及可用性状态。

## 两条真实公开材料预演

本轮使用独立数据库与公开材料，没有将现有私人课题用于模型预演。

**文献路径。** 实际读取 [PubMed PMID 33782057](https://pubmed.ncbi.nlm.nih.gov/33782057/) 的 PRISMA 2020 摘要，采用“公开摘要理解计划”，再讨论报告规范的用途与边界。真实模型任务完成，记录 1 次模型调用与 5 个引用。该材料仅为单篇摘要，不能证明已经完成系统综述、全面检索或全文审计。

**外部执行路径。** Codex 实际运行本地 Python 对同一公开摘要做文本计数，结果为 877 个字符、126 个空白分词，Python 3.14.6。保存实际执行人、代码、环境、结果与两个 JSON 原附件，明确这是工程计数验证，未开展临床实验。将记录用于没有文献输入的后续讨论，实际完成 1 次模型调用。

第二条预演暴露了两个断点并完成修复：旧入口在运行时仍要求文献，造成调用前失败；随后模型引用“局限”字段中的原句，被仅定位正文的旧校验拒绝。修复后保留原模型响应，使用已有本地重新校验完成任务，**没有再次调用模型**。失败、调用和重新校验各自留存，没有改写为一次无故障运行。

两条预演合计 **2 次真实模型调用，模型为 GLM-5.3-Flash，费用未知**；本地重新校验调用为 0、额外模型费用为 0。结构和引用位置检查通过不等于研究解释全部正确；真实输出中的个别文件名表述有缩写，原文保留，附件身份以实际元信息为准。正式论文仍需逐条判断科学含义和引文支持。

## 剩余边界与下一阶段

- **用户连续体验与同题对照尚未完成。** 工程可以冻结为共同起点，但不能声称工作台已优于 GPT 网页版，或已代替用户完成整个科研周期。
- 实际实验、统计计算和结果解释仍由研究者选择工具并核对。本轮支持回接记录，不提供通用统计执行或自动实验能力。
- 结局／单位检查是确定性文字线索；摘要未报告仍为未知。正式方法、数值或强主张需要针对性核查，不能因任务成功而升级事实状态。
- 原有未知依赖不自动补造；文件保留不等于全文内容自动入模。图稿只有实际使用的方案、结果与数据才登记为依据。
- 构建仍有既有前端主包体积提示（约 631KB，gzip 约 198KB），本轮不将它包装为性能优化已全部完成。多用户托管、跨设备同步、自动素材发现与运行时生图不在本轮交付中；D-054 的配图方向继续保留。

最值得接着做的是：从你已有课题的当前进度，完成一个具体研究步骤，例如采用当前方案、整理一份实际结果或完成一节有依据的正文；期间只记录必须重述、搬运、补救或核对的断点。完成后冻结该步骤的工作台成果，再与“提示词＋GPT 网页版”的同一步骤比较。下一次优化优先处理真实阻断、重要失真和反复返工，不先增加模块数量。
